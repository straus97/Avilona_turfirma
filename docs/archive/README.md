# Архив документации Avilona_turfirma

`docs/archive/legacy-pre-rebuild/` содержит исторические документы проекта
(32 файла), созданные до восстановления базы данных, переработки
документации и последующих функциональных доработок (Stage 5+). Эти файлы
были перемещены из корня `docs/` без изменения содержимого.

## Важно

Файлы внутри `docs/archive/legacy-pre-rebuild/`:

- НЕ являются актуальным источником истины по проекту;
- могут содержать устаревшие маршруты, имена баз данных, команды,
  настройки, интеграции, архитектурные предположения и инструкции по
  окружению;
- могут описывать небезопасные или деструктивные операционные шаги
  (например, сброс/пересоздание базы данных), больше не допустимые без
  отдельного guarded-плана;
- могут описывать уже устранённые проблемы или завершённые этапы как
  незавершённые;
- сохранены только для истории требований, решений и хода восстановления
  проекта.

Команды из архивных документов **нельзя выполнять без отдельной проверки**
их актуальности и безопасности.

Приоритет источников истины (от высшего к низшему):

1. текущая ветка, local HEAD, live origin HEAD, working tree и текущие
   repository guards;
2. исходный код и тесты на этом HEAD;
3. [`docs/README.md`](../README.md) и [`docs/roadmap.md`](../roadmap.md);
4. последний verified handoff и Project Sources set для того же pushed
   HEAD;
5. историческая evidence (recovery/closure отчёты и т.п.) — только как
   вспомогательный контекст.

Архивные документы (`legacy-pre-rebuild/`) стоят вне этой иерархии и не
должны молча использоваться как руководство к текущей реализации —
только как исторический контекст после сверки с пунктами 1–5.

## Что нельзя делать по архивным инструкциям без отдельного плана

Не выполнять автоматически:

- `composer update`;
- `npm update`;
- `npm audit fix`;
- `php artisan migrate:fresh`;
- `php artisan migrate:refresh`;
- `php artisan db:wipe`;
- seed/import/reset-команды;
- команды против canonical MySQL;
- реальные внешние API-запросы;
- операции с production-интеграциями;
- команды с устаревшими именами баз данных или путями;
- запуск глобального `php`, если не указан проектный PHP:
  `C:\wamp\bin\php\php8.3.32\php.exe`.

## Актуальные документы

Основными активными документами проекта должны оставаться:

- [`docs/README.md`](../README.md)
- [`docs/roadmap.md`](../roadmap.md)

Они имеют приоритет над любым содержимым `legacy-pre-rebuild/` и должны
отражать текущее состояние ветки, завершённые этапы, активный этап
(на момент последнего обновления — Stage 0–9 COMPLETE, Stage 10 IN
PROGRESS), известные ограничения и следующий guarded шаг.

## Назначение архива

Архив нужен для сохранения:

- истории восстановления проекта;
- старых требований и решений;
- причин ранее принятых архитектурных мер;
- материалов для расследования регрессий;
- контекста, который может быть полезен при аудите.

Архивные документы не следует удалять без отдельного решения, но их также не следует использовать как руководство к действию без проверки актуальности.
