## Цель проекта

Создать надёжный, безопасный веб-сайт и внутреннюю систему бронирования для туристического агентства «Авилона».
Три основные роли: турист, менеджер, администратор.
Система должна обеспечить полный жизненный цикл заявки, безопасный обмен документами
и управляемое взаимодействие между клиентом и менеджером.

## Принципы выполнения

- Один маленький семантический слой за раз.
- Read-only preflight перед каждым патчем.
- Чёткий список разрешённых файлов в каждом слое.
- Ручное ревью diff перед коммитом и пушем.
- PHPUnit всегда на SQLite `:memory:`.
- Никаких изобретённых дедлайнов — оцениваем по факту выполнения.

## Этап 5. Полный жизненный цикл заявки 📋

Следующий функциональный приоритет. Разбивается на отдельные слои:

1. **Read-only аудит** — создание, владелец, назначение менеджера, текущие статусы, разрешения ролей, маршруты/контроллеры/представления/тесты.
2. **Матрица переходов статусов** — определить допустимые переходы и покрыть тестами.
3. **Улучшение формы создания заявки** — только при обнаружении пробелов в ходе аудита.
4. **Правила переназначения менеджера** — отдельный слой.
5. **История / журнал аудита заявки** — отдельный слой.
6. **End-to-end сценарий:** турист создаёт → администратор назначает → менеджер обрабатывает → обмен сообщениями/документами → подтверждение → завершение/отмена.

## Критерии MVP

- Публичные страницы работают.
- Регистрация, вход и верификация email работают.
- Турист создаёт и просматривает собственную заявку.
- Администратор назначает менеджера.
- Назначенный менеджер обрабатывает заявку.
- Изоляция ролей выполняется.
- Базовый обмен сообщениями работает безопасно.
- Документы бронирования передаются безопасно.
- Критичное управление контентом администратором работает.
- Адаптивный UI.
- Полный PHPUnit и ролевой smoke-тест проходят.
- Проверенный план резервного копирования и отката для продакшн.
